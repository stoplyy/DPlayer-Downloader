# Edge / Chrome 商店分发改造方案

## 文档状态

**已评审并进入实现，正式发布待维护者配置与验收。** 2026-10-16 用户确认同时发布 Edge 与 Chrome，商店 ID、发布者与签名信息在手动发布时填写。此文档是设计资料，不是额外执行授权。实现与发布步骤以 `docs/release-checklist.md` 为准；下载核心、任务协议和本机执行模型沿用现有设计。

## 产品决策

采用 **Microsoft Edge Add-ons / Chrome Web Store 扩展 + 独立 Windows Host 安装器** 分发。两个商店共用扩展源码，各自生成 ZIP；Windows 安装器采用 Inno Setup 当前用户安装，同时注册 Edge 与 Chrome。商店包移除开发公钥，Host 精确允许两个商店最终确认的 ID。后文原方案中的 Edge-only 限定按这个用户确认的决定修正：

1. 扩展分别上架 Microsoft Edge Add-ons 与 Chrome Web Store。商店包只包含浏览器扩展文件。
2. 本机 Native Messaging Host、yt-dlp、ffmpeg/ffprobe 通过项目官方发布页面提供的 Windows 用户级安装器单独安装。
3. 扩展在商店安装后即可扫描页面、显示界面和检测 Host；下载、队列及本机任务管理功能要求 Host 已安装。
4. 首次点击需要 Host 的操作时，若 Host 不可用，扩展解释原因并提供官方安装器链接及重试入口。扩展不下载或静默运行安装器，也不承诺“仅安装商店扩展即可下载”。
5. Host 安装器只安装/更新/卸载 Host 与运行依赖，并注册当前用户的 Native Messaging manifest。安装完成后回到扩展点击“重试连接”即可；不要求开发者模式、不要求 Load unpacked、不要求用户手动编辑注册表或复制文件。
6. 暂不做云端下载、浏览器内原生下载引擎、Windows 服务或自动更新服务。Host 更新通过官方安装器发布；扩展通过商店更新。
7. 一期完整下载仅支持 Windows 10/11 x64。macOS、Linux、ChromeOS 上如可安装 Edge/Chrome 扩展，仅开放页面扫描、可用预览与候选选择；下载、大小探测和本机任务管理需要 Windows Host。Windows ARM64 与 32 位 Windows 不属于一期支持目标。商店简介、首次使用提示、安装说明和隐私政策必须一致披露此范围。

这是浏览器 Native Messaging 的平台边界：浏览器商店管理扩展，系统安装器管理本机 Host。安装器可以与扩展配合提供一键引导，但不能由商店扩展代替系统安装步骤。

## 面向用户的流程

### 首次安装

1. 用户在 Edge 商店安装扩展。
2. 扩展启动后进行有限的 Host 健康检查；未安装时仍允许打开 UI 和扫描页面，清晰显示“本机下载组件尚未安装”。不得将 Host 缺失呈现成扩展损坏或要求刷新/重装扩展。
3. 用户点击下载或其他依赖 Host 的功能时，显示安装说明、官方 HTTPS 安装器链接、需要安装的组件、Windows/架构要求及卸载说明。
4. 用户主动下载并运行签名的安装器。安装器显示产品/发布者信息、安装路径、将注册 Native Messaging Host、将安装的依赖和卸载入口；不修改系统级配置、不请求管理员权限，除非选定的安装技术确有必要并经方案评审。
5. 安装成功后，安装器提供“返回 Edge”操作（可选地打开 `edge://extensions` 或项目帮助页；不尝试自动启用或操纵扩展）。扩展的“重试连接”建立 Native Messaging 连接并确认协议版本。

### 已安装但不可用

- Host 缺失/未注册：给出安装器链接和安装步骤。
- Host 协议版本不兼容：说明需要更新 Host，链接到官方更新安装器；不得静默执行更新程序。
- Host 启动失败：给出可操作错误、诊断信息入口和官方支持链接，不暴露签名 URL、Cookie 或敏感本机路径。
- 安装器取消或失败：扩展保持可用的非 Host 功能；提供重试和错误说明。

### 卸载

- 扩展通过 Edge 扩展管理页卸载。
- Host 通过 Windows“已安装的应用”卸载，或官方安装目录提供的卸载入口移除。
- Host 卸载默认删除程序文件和 Native Messaging 注册，保留用户下载、任务状态和设置；提供清楚且单独确认的可选数据清理操作。
- README 和商店说明分别解释两种卸载对象，避免用户误以为卸载扩展会自动卸载 Host。

## 架构与信任边界

```text
Microsoft Edge Add-ons                     官方项目发布页
        │                                      │
        ▼                                      ▼
MV3 扩展 ─── Native Messaging ───► 已安装的 Windows Host + yt-dlp/ffmpeg
   │                                      │
   ├─ 页面扫描仅由用户触发                 ├─ 仅本机下载和任务管理
   ├─ Host 状态/安装说明                   ├─ 严格校验扩展消息
   └─ Cookie 按任务征求权限                └─ 不向项目服务器上传媒体/Cookie
```

- 商店扩展包和 Windows 安装器是两个独立制品、独立版本号/发布说明；每个制品都可单独升级。
- Native Messaging Host manifest 中的 `allowed_origins` 必须精确包含经验证的 Edge 与 Chrome 商店正式扩展 ID。不得保留开发/临时 ID 或宽泛来源。固定公钥仅用于开发，商店包不包含该 key；分别以 Edge Partner Center 和 Chrome Web Store 最终分配/确认的 ID 为准。
- Host manifest 使用 `chrome-extension://<正式扩展ID>/` 来源格式（Edge Native Messaging 采用此格式），安装器生成后验证完整字段、绝对 exe 路径和来源 ID。
- 安装器不得从未固定/未审查的 URL 拉取可执行文件。yt-dlp、ffmpeg/ffprobe 和 Host 均随签名安装器打包；依赖版本、SHA-256、来源归档和许可材料在 release build 中固定且校验。
- 下载仍在用户设备运行。扩展只把用户确认的任务经 Native Messaging 交给 Host；默认不使用 Cookie。用户启用登录态时仍按现有逐主机授权设计执行。
- 扩展商店页面和隐私政策必须披露页面媒体信息的读取时机、可选 Cookie 权限、与本机 Host 的通信、本机存储、没有上传/遥测（若实现确实如此）、卸载/数据删除方式及支持边界。任何实际数据流变化必须同步更新披露。

## 改造任务

### A. 形成正式扩展发布制品

- 新增独立扩展打包命令/脚本，只收集 Edge 扩展运行必需文件及必要 LICENSE；输出可直接提交商店的 ZIP，ZIP 根目录直接含 `manifest.json`，不包含 Native Host、安装脚本、开发 fixture、测试文件或 `.devbuild` 产物。
- 构建前执行 `sync-shared.mjs --check`；打包后验证 manifest JSON、所有本地引用文件存在、无 source copy 漂移、无测试/开发文件、无远程可执行代码和意外权限。
- 补齐商店扩展所需图标尺寸/manifest icons、产品截图和清晰描述。统一产品名、中文/英文简介、版本号和受支持平台信息。
- 权限维持最小化：基础权限解释用途；Cookie 与站点访问继续为可选且仅在明确用户动作时申请。若现有 `storage`、`alarms` 或宽泛可选 host pattern 被保留，在审核材料中逐项说明实际功能；不得申请未来备用权限。

### B. 把安装/升级/卸载迁移为用户级 Host 安装器

- 选择并记录 Windows 安装技术（建议可签名、支持 per-user、可升级/卸载的成熟安装器；实现 Agent 先检查仓库/部署约束，再定具体技术）。不以开发者 PowerShell 脚本作为面向普通用户的唯一安装体验。
- 安装文件布局包括 Host exe、yt-dlp、ffmpeg/ffprobe、license/NOTICE、生成后的 Native Messaging manifest、卸载器及版本元数据；Edge 扩展不复制到本地作为 unpacked 扩展。
- 安装器读取统一的正式扩展 ID 配置生成/校验 manifest，只注册 HKCU 下的 Edge 与 Chrome Native Messaging 项；路径安全处理，写入原子化，失败时回滚本次写入。
- 支持安装、同版本修复、版本升级、卸载；升级前停止旧 Host 进程；卸载默认保留用户数据。明确覆盖旧开发版安装的迁移行为，不能静默删除下载或任务状态。
- 对安装器及内含可执行文件实施代码签名；发布流程在签名证书不可用时明确阻断正式 release，而不是输出看似正式的无签名安装包。开发构建可有显著标记的非发布模式。
- 安装器支持无管理员权限的当前用户安装；若技术方案不能做到，记录原因并先评估替代方案，不能悄悄扩大权限。

### C. 扩展内 Host 检测与安装引导

- 将桥接状态归一为：checking、ready、not-installed、incompatible、failed。首次检查超时有限，不阻塞扩展弹窗/扫描。
- 区分“扩展可运行”和“下载 Host 可用”。Host 不可用时保留扫描和设置等不依赖 Host 的功能。
- 在首次依赖 Host 的操作处显示正式安装器 HTTPS 链接、必要性/组件说明、版本要求、安装后重试按钮和帮助链接。
- 安装器下载链接不可由动态第三方内容覆盖；优先使用项目控制的 HTTPS 发布地址。下载完成/返回不等同于 Host 已安装，必须再次用 Native Messaging 握手验证。
- 对版本不匹配提供 Host 更新链接与重试，不自动下载、执行或注册更新程序。
- 若发布页 URL、商店 ID 或最低 Host 版本需要配置，集中在单一 release 配置并做格式/一致性检查，避免散落硬编码。

### D. 商店合规、隐私和发布材料

- 新增公开 HTTPS 隐私政策，实际说明：用户主动扫描时读取的页面/媒体信息；Cookie 为可选、逐次授权及其用途；Native Messaging 传给本机 Host 的数据；本地任务状态、签名 URL 加密和 Cookie 临时文件；数据保留/删除；是否存在遥测/第三方服务；联系方式及政策更新方式。
- 在扩展首次使用体验中显示简明的数据处理/Host 依赖提示，并链接完整政策；商店 listing 配置隐私政策 URL、权限理由和所有数据处理问卷。
- 准备商店名称、短/长描述、图标、真实界面截图、支持 URL、隐私政策 URL、测试说明。准确说明 Windows 10/11 x64 + Edge/Chrome 120+ 是一期完整下载环境；其他可安装扩展的平台仅能扫描与选择；本机 Host 必装、当前站点/媒体格式限制和授权下载要求。
- 不将商店审核测试引向真实受限媒体；提供本地 fixture/演示流程及无真实账号测试说明。

### E. 依赖与供应链发布门禁

- 填充 yt-dlp/FFmpeg 源码归档 SHA-256，并独立核实归档对应二进制版本；完成完整第三方 notices（包括 FFmpeg 外部库和 PyInstaller/runtime）。GPL/再分发审查未完成时不得分发依赖包。
- 增加 release 清单，记录扩展版本、Host 协议版本、Host 版本、各依赖版本/哈希、安装器哈希、签名状态、商店 ID 和源代码/许可证链接。
- 安装器、Host、下载依赖每次发布均可追溯；发布页提供签名信息、SHA-256、变更记录、系统要求和卸载指南。
- 正式发布前核实 Inno Setup 安装器工具链本身的分发许可，并记录审查结果与工具版本。
- 不在本次计划引入自动更新服务。安装器更新链接由扩展打开官方发布页面；扩展通过握手提示 Host 与协议版本不兼容。

## 验收标准

### 商店扩展包

- 生成 ZIP 后根目录有有效 MV3 `manifest.json`，可由 Edge 加载；无本机二进制/安装器、测试 fixture、开发路径或无关文件。
- 商店提交使用的 manifest 权限与 listing/隐私说明逐项吻合；正式扩展 ID 已由目标商店确认。
- 版本号、图标、所有资源路径和脚本类型符合 Edge 商店要求；无加载错误、缺失资源和未解释权限。

### Host 安装器

- 在干净 Windows 当前用户账户（无管理员权限、无预装 Python）可以安装、注册、启动 Host 并与商店 ID 扩展完成 ping/协议握手。
- 任何非正式扩展 ID 均不能连接 Host； manifest 的来源严格等于两个正式 ID。
- 用户运行安装器前不安装任何东西；仅下载商店扩展可使用不依赖 Host 的功能，依赖 Host 的操作显示明确引导。
- Host 安装失败、取消、缺失和版本不兼容均可恢复；升级、修复、卸载不会误删下载、任务或用户设置。
- 正式安装器及可执行文件签名可验证，签名者/产品信息一致；安装/卸载日志不含 Cookie 或签名 URL。

### 产品披露与发布

- 首次使用提示、商店 listing、隐私政策和实际数据流一致；包含 Host 必装、安装来源、权限、数据位置/删除和支持信息。
- yt-dlp、FFmpeg、ffprobe、PyInstaller/runtime 的版本、哈希、源代码和许可证材料完整且经核验；release 门禁拒绝空哈希、缺失 notices、未签名制品和未设置正式扩展 ID。
- 用本地测试页/本地 HTTP fixture 验证扫描与下载链路；不向真实站点发送测试下载请求。

## 建议实现顺序

1. 确认商店正式扩展 ID、官方 HTTPS 发布域名、最低 Windows/Edge 版本和签名/安装技术。
2. 更新架构决策文档，固定双渠道发布契约与用户状态/错误文案。
3. 增加独立商店 ZIP 构建和制品校验。
4. 实现 per-user Host 安装器、升级/卸载及严格正式 ID 注册。
5. 实现扩展内 Host 检测、缺失/过期提示、官方安装链接和重试。
6. 写隐私政策、首次使用披露、商店 listing/审核材料。
7. 完成依赖许可与源码核验、代码签名、发布清单和发布流程。
8. 执行验收矩阵，先用未公开/隐藏商店提交完成认证，再正式发布。

## 尚待确定的发布配置

以下是执行所需输入，不改变以上产品决策：

- Edge Partner Center 与 Chrome Web Store 确认的两个正式 extension ID。
- 项目官方网站/发布页、隐私政策稳定 URL、支持/联系 URL。
- 代码签名证书及受信任发布者名称。
- 最低 Windows 版本、CPU 架构（首发是否仅 x64）和最低 Edge 版本。
